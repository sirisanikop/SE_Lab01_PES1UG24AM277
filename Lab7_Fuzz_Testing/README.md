## 1. Overview & Objective

The objective of this lab is to explore **fuzz testing (property-based testing)** as a dynamic software testing and quality assurance methodology. Fuzzing involves feeding automated, randomized, malformed, and adversarial data to functions to identify edge cases, input validation gaps, and unhandled exceptions that cause crashes or security vulnerabilities.

Using Python's **Hypothesis** library along with **Pytest**, this lab focuses on:
- Uncovering input validation bugs in an elevator dispatch processing module (`elevator_dispatch.py` / `processor.py`).
- Formulating property-based fuzz tests to automatically discover minimal failing inputs.
- Hardening the application using defensive programming principles so that all functions handle unexpected inputs gracefully without terminating abnormally.

## 3. The Three Functions Under Test

| Function | Expected Input Format | Buggy Behavior on Edge Cases | Hardening Applied |
| :--- | :--- | :--- | :--- |
| `parse_request(text)` | `'FROM->TO'` (e.g. `'5->9'`) | Crashes with `AttributeError` on `None`, `ValueError` if `'->'` is missing, duplicate, or tokens are non-numeric. | Validates string type, ensures exact occurrence of delimiter, converts safely with `try/except (ValueError, TypeError)`, returning `None` on error. |
| `total_travel(floors_csv)` | Comma-separated floors (e.g. `'1,5,3,9'`) | Crashes with `AttributeError` on `None`, `ValueError` on empty string `""` or non-integer tokens, single floor issues. | Validates string type, trims whitespace, filters empty tokens, returns `0` if fewer than 2 valid floors or on parsing exceptions. |
| `load_percent(text)` | `'LOAD of CAPACITY'` (e.g. `'450 of 630'`) | Crashes with `AttributeError` on `None`, `ValueError` on missing delimiter or empty tokens, `ZeroDivisionError` if capacity is `0`. | Validates format, guards against `capacity <= 0`, catches `ValueError` and `ZeroDivisionError`, returning `0` safely. |

### Step 3: Complete Hypothesis Test Suite
Tests in `test_elevator_dispatch.py` specify the property invariant that functions must **never crash** under any input generated by `@given(st.text() | st.none())`:
```python
from hypothesis import given, strategies as st
from elevator_dispatch import parse_request, total_travel, load_percent

@given(st.text() | st.none())
def test_parse_request_no_crash(s):
    try:
        parse_request(s)
    except Exception as e:
        assert False, f"parse_request crashed with: {e}"

@given(st.text() | st.none())
def test_total_travel_no_crash(s):
    try:
        total_travel(s)
    except Exception as e:
        assert False, f"total_travel crashed with: {e}"

@given(st.text() | st.none())
def test_load_percent_no_crash(s):
    try:
        load_percent(s)
    except Exception as e:
        assert False, f"load_percent crashed with: {e}"
```

### Step 4: Run Tests to Expose Vulnerabilities
```bash
pytest test_elevator_dispatch.py
```
*Result:* All 3 tests fail immediately (`3 failed`). Hypothesis identifies falsifying examples such as `s=''`, `s=None`, `s=' of '`, and zero capacity.  
*Screenshot:* `screenshots/step4_failing_tests_output.png`

## 5. Summary of Falsifying Examples Discovered

| Function | Minimal Failing Input | Exception Raised | Root Cause |
| :--- | :--- | :--- | :--- |
| `parse_request` | `s = ''` | `ValueError` | `text.split('->')` returned 1 element; unpacking into 2 variables failed. |
| `parse_request` | `s = None` | `AttributeError` | Calling `.split()` on `None` object. |
| `total_travel` | `s = ''` | `ValueError` | `floors_csv.split(',')` produces `['']`; `int('')` fails to parse. |
| `total_travel` | `s = None` | `AttributeError` | Calling `.split()` on `None` object. |
| `load_percent` | `s = ' of '` | `ValueError` | Left and right tokens are empty strings; `int('')` fails to parse. |
| `load_percent` | `s = '100 of 0'` | `ZeroDivisionError` | Integer division `//` by zero when capacity is 0. |
